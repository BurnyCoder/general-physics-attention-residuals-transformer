# Additional initialization-only baselines

Status: requested by the user on 2026-10-26 **after the trained-model results were known**. This is a post-hoc descriptive control study. This document and its execution source are published before the first initialization-only evaluation. The original [preregistered protocol](protocol.md), training outcomes, primary endpoint, six-pair confidence interval, and permutation test remain unchanged.

## Fixed design before execution

- Evaluate all four architectures at **zero optimizer updates**: Standard and Block at seeds 0–5; Full and Uniform Block at seeds 0–2. Use the original published 18-run order. Do not add or select seeds after seeing these control results.
- Reconstruct each initialized model with the **same `make_model(frozen_config, mode, seed)` constructor used by training**, the same pinned upstream sources, and the same locked runtime. These are reconstructed initializations, not historical step-zero checkpoint files; training did not archive step-zero weights. Save the reconstructed tensor checkpoint and hashes. Verify identical shared-backbone tensor hashes across architectures for each seed, zero pseudo-queries, and unit key RMS scales. Verify the complete parameter/buffer hash is unchanged after inference.
- Load no trained weights, instantiate no optimizer, call no backward pass, and freeze parameters in evaluation mode. An untrained GPhyT still has the original architecture and outer next-state update; it is distinct from the parameter-free persistence baseline. At zero queries, Block and Uniform Block use equal routing weights; their duplicate initial states are a useful consistency check, not independent architecture evidence.
- Reuse the complete official test population, selected training-only normalization, active-field masks, four observed context frames, three fixed windows per trajectory, stride one, BF16 autocast, and 1/12/24-step autoregressive NMSE. Reuse `evaluate_model` and its strict failure propagation. Do not change epsilon, field weighting, forecast origins, or the reported primary endpoint.
- Summarize each architecture over its complete original seed set, alongside its trained final-checkpoint counterpart on the same seed set. Missing/divergent constituents yield undefined means. Retain per-seed and per-trajectory outcomes and descriptive seed uncertainty. Add no confirmatory significance test or claim to the original hypothesis.
- Show seed zero, the first test trajectory and first window, at forecast step twelve for both datasets. Compare ground truth, persistence, initialized model, and trained counterpart with the same unclipped color range within each dataset/architecture row; show nonfinite values explicitly. These illustrative cases were fixed before the trained-model results and are not selected for favorable appearance.

## Execution and budget

Run `uv run --no-sync python -m gphyt_attnres_study untrained` only after publication. The existing `Budget("evaluate")` acquires the exclusive GPU ledger and independent watchdog. The original evaluation allocation is two hours; before this extension it had used 2,364.4755025 seconds, leaving about 80.6 minutes. Previous ordinary-evaluation timings suggest roughly 30 minutes for the 18 initialized controls, but the existing cap governs actual execution. The total project cap remains 24 GPU-hours. There is no training or budget reset.

Completed attempts are skipped on subsequent commands. Failed or interrupted attempts remain recorded and are not silently retried. A budget stop leaves remaining controls visibly missing. Diagnose any genuine implementation failure before an explicitly documented repair; never substitute another seed or change the control definition.

Artifacts live under `STUDY_ROOT/untrained/`, with preview arrays named `untrained_<mode>_seed<seed>_<dataset>.npz` in the existing `visuals/` directory. They are kept outside the original `evaluation/` discovery so `analyze` cannot incorporate them into the confirmatory result. Public tables, raw metrics, field figures, and checkpoint provenance are added to the reports, README, and paper only after measured outputs exist.

The implementation follows the official [PyTorch reproducibility guidance](https://docs.pytorch.org/docs/2.14/notes/randomness.html), [evaluation-mode contract](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Module.html#torch.nn.Module.eval), the pinned GPhyT constructor, and the existing study evaluator. Evaluation mode does not itself disable gradients; the control explicitly freezes parameters and the existing forecast function runs under `torch.no_grad()`.
