# Focused implementation and scientific-method review

Reviewed before confirmatory training on 2026-10-25. This records one focused pass over correctness, reliability, security, maintainability, and scientific validity; it is not an independent external audit. The approved [protocol](protocol.md) remains the source of scientific decisions, and [development learnings](../reports/development.md) record reproduced failures and fixes.

| Area | Evidence and resolution | Remaining limit |
|---|---|---|
| Source reuse and equations | Pinned upstream files and licenses are retained. Independent forward/gradient equations, raw-writer fixtures, boundary/reset tests, and exact standard-path parity protect the architecture change. | Execution equivalence does not imply improved forecasts. |
| Data and leakage | Official source selection is published before training. Tests cover real HDF5-shaped input, field masks, uniform-grid resizing, train-only statistics, split duplication, and paired sampling. Sparse segmented files cannot pass the fallback by size alone. | Complete real-data split and normalization checks require all downloads; their findings must be reported after preparation. |
| Causal evaluation | Forecasting accepts context without future truth. Interventions compare identical trajectory hashes with ordinary routing. Active-field masking occurs before loss/error arithmetic; nonfinite active rollouts propagate to undefined aggregates. | The first-four-trajectory intervention subset is fixed by manifest order and is not balanced over every parameter. It cannot establish a universal mechanism. |
| Statistical validity | Six independent seed pairs determine the primary test and interval. The minimum meaningful effect, variance assumptions, exact sign test, and missing-result policy were specified in advance. Populated reporting fixtures verify the complete analysis-to-table/figure path. | The normality/exchangeability assumptions are substantive; six pairs can have low power. No significant result is guaranteed. Descriptive secondary intervals have no multiplicity correction. |
| Reliability and budget | Checkpoint tests compare resumed and uninterrupted optimizer steps and sample RNG. A subprocess fixture verifies that an independent supervisor stops a noncooperating worker and records the hard stop; normal completion cancels its own supervisor. | Hard stops can lose updates since the last durable checkpoint. Their consumed wall time remains charged. Host shutdown or hardware failure is outside ordinary continuation. |
| Reproducibility | A portable data fingerprint excludes only local paths/timestamps. Training checks the published freeze, source files, locked dependencies, and upstream Git state. `reproduce` adopts the original horizon after verifying scientific inputs. | Deterministic settings do not promise bitwise agreement across different GPU hardware or library versions. |
| Security and publication | Model releases allowlist safetensors weights, configurations, normalization, metrics, manifests, licenses, and model cards. Credentials and environments are ignored. Local optimizer pickle files are not publicly loaded. Pages deploys only `site/`. | Authentication and upload availability must be confirmed during the actual release, and a downloaded checkpoint must still be re-evaluated. |
| Maintainability and presentation | One phase-based entry point delegates to focused modules. Reporting reuses measured tables, and public/local viewers consume shared evidence. The provisional PDF and deployed pending-results viewer have been visually checked. | Actual forecast, routing, and final manuscript views require another verification when measured data become available. |

All implementation changes above precede the measured training-schedule freeze. No endpoint, dataset selection, seed, optimizer setting, or stopping rule was chosen from test accuracy. This review does not mark unfinished experiments or publication work complete.

Relevant primary guidance: [PyTorch reproducibility](https://docs.pytorch.org/docs/stable/notes/randomness.html), [autograd and masking](https://docs.pytorch.org/docs/stable/notes/autograd.html), [SciPy paired permutation testing](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html), [Lones on ML pitfalls](https://arxiv.org/abs/2108.02497), and the [NeurIPS checklist](https://neurips.cc/public/guides/PaperChecklist).
